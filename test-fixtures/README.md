# Test fixtures

Tiny real projects the [smoke test](../.github/workflows/smoke-test.yml) runs
the reusable pipelines against on every change to this repo. They exist so a
workflow edit has to *actually work* — build, test, scan, pass — before it can
merge and reach consumers.

- **`gradle/`** — the smallest possible Gradle project (plain Java + JUnit 4,
  one test). Exercises `gradle-test.yml`, including the wrapper-validation and
  caching path. No Kotlin plugin on purpose: `gradle-test` is
  language-agnostic and skipping the Kotlin toolchain keeps the smoke test fast.
- **`ios/`** — a minimal SwiftUI app + XCTest target. Exercises
  `ios-test.yml` (simulator build + test, no signing) and doubles as the
  `ios-compliance.yml` fixture: it ships a `PrivacyInfo.xcprivacy` and an
  Info.plist with `ITSAppUsesNonExemptEncryption` declared.

The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)
from `ios/project.yml`, and the generated `Fixture.xcodeproj` is **committed**
so CI never needs XcodeGen. After editing `project.yml`:

```bash
cd test-fixtures/ios && xcodegen generate
```

Keep these fixtures boring. They are not examples of good app architecture —
they are the minimum surface that proves the pipelines run.
